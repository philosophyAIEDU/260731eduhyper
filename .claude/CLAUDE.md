# HyperFrames 영상 제작 프로젝트

이 파일은 **Claude Code가 읽는 규칙서**입니다. 사용자가 몰라도 되도록, 이 프로젝트에서
반복해서 걸리는 함정과 검증된 절차를 여기에 적어 둡니다. 작업 시작 전에 반드시 읽으세요.

> **경로 기준:** 프로그램과 코드는 전부 `5_etc/` 안에 있다. 이 문서의 `scripts/` · `videos/` · `remotion/` ·
> `assets/` · `templates/` 같은 상대 경로와 명령은 **`5_etc/` 에서 실행한다.**
> 이 규칙서는 루트에서 자동으로 읽히도록 `.claude/CLAUDE.md` 에 있다.

## 🚨 1. 경로에 한글이 있으면 안 됩니다 (가장 중요)

**HyperFrames CLI는 비ASCII(한글) 경로에서 네이티브 크래시합니다.**
에러 메시지 없이 exit 127 / Windows 0xC0000409 로 조용히 멈추기 때문에,
모르면 원인 파악에만 한 시간 이상 걸립니다.

```
❌ C:\Users\user\바탕화면\양자컴퓨터\  → init·render 전부 조용히 실패
✅ C:\Users\user\hyper\quantum\        → 정상
```

**작업 시작 전에 항상 현재 경로를 확인하세요.**

```bash
pwd   # 한글이 보이면 여기서 멈춘다
```

원본 영상·대본이 한글 폴더에 있는 것은 **괜찮습니다**. ffmpeg·python은 한글 경로를
정상 처리합니다. HyperFrames 프로젝트 폴더만 ASCII면 되고, 완성된 MP4는 마지막에
한글 폴더로 복사하면 됩니다.

### 데스크탑 앱에서 작업하는 경우

이 키트가 안내하는 정상 경로는: 사용자가 처음부터 자료를
`C:\Users\<사용자>\hyper\source` (영어 경로)에 모아 둔 채로 요청합니다.
이 경우 `hyper` 가 곧 작업 폴더이므로 옮길 것이 없습니다 —
`hyperframes-starter-kit` 을 `hyper` 에 아직 안 넣었으면 그것만 복사하고
바로 시작하세요.

만약 사용자가 (안내를 못 보고) 자료를 여전히 한글 폴더에 둔 채로 요청한다면,
**사용자에게 폴더를 옮기라고 시키지 말고 직접 처리하세요:**

1. `C:\Users\<사용자>\hyper` 를 작업 폴더로 쓴다 (없으면 새로 만든다 —
   영상마다 새 이름을 짓지 않고 항상 이 폴더 하나를 재사용한다)
2. `hyperframes-starter-kit` 을 그 안으로 복사한다
3. 원본 자료 폴더는 접근 권한만 받아서 읽는다 (옮기지 않는다)
4. 완성된 MP4 는 `hyper` 폴더에 두거나, 사용자가 원하면 원래 폴더로도 복사한다

공통: `hyper` 안에 이전 영상의 씬 파일이 남아 있다면, 새 영상을 시작하기 전에
정리하세요 (섞이면 검증에서 안 잡히는 버그가 됩니다).

입문자는 이 제약을 몰라도 되게 하는 것이 목표입니다. 경로 이야기로
사용자를 붙잡지 마세요 — 조용히 올바른 곳에서 작업하고, 결과만 전달하세요.

## 2. 이 프로젝트의 작업 흐름

입력은 4개 파일입니다 (`templates/` 에 양식이 있습니다).

| 파일 | 내용 |
| --- | --- |
| `PART 0. 초고 영상.mp4` | 내레이션이 녹음된 원본. **오디오만** 씁니다. |
| `PART 1. 낭독 대본.txt` | 확정 대본 |
| `PART 2. 씬별 지시서.txt` | 씬별 화면 요소 / 애니메이션 / 온스크린 텍스트 |
| `PART 3. 제작 프롬프트.txt` | 컬러·애니메이션 세부 사양 |

PART 1~3 은 사용자가 직접 쓰거나, `docs/claude-project/` 의 Claude 프로젝트로
생성한 것일 수 있습니다. 후자의 경우 **`PART 4. 수업 연계 자료`** 라는 파일이
함께 있을 수 있는데(대학 강의 모드), 이건 확인문제·LMS 설명문 등 강의 운영용
자료라 **영상 제작에는 쓰지 않습니다.** 무시하고 PART 1~3만 사용하세요.

절차:

1. **오디오 추출 + 전사** — `scripts/2-오디오추출-전사.ps1`
2. **실제 발화 타이밍에 씬 배치** (아래 3번 참고)
3. **씬별 서브컴포지션 작성** — `compositions/scene-skeleton.html` 복사해서 시작
4. **검증** — `npx hyperframes check`
5. **눈으로 확인** — `npx hyperframes snapshot --at <초,초,초>`
6. **렌더** — `npx hyperframes render -o out.mp4`
7. 완성본을 원본 폴더로 복사

또 하나: 원본 오디오 앞에 대본에 없는 인사말("안녕하세요, ○○입니다")이 붙어 있는

## 5. HyperFrames 작성 규칙 (자주 틀리는 것)

- 서브컴포지션은 `<style>` · 마크업 · `<script>` 를 **전부 `<template>` 안에** 넣습니다.
  `<head>` 에 둔 `<style>` 은 렌더 시 통째로 버려집니다.
- 서브컴포지션 루트는 **`#root` 로 스타일**합니다. 클래스로 스타일하면 조용히 전부 무시됩니다.
- 호스트 슬롯의 `data-composition-id` = 서브컴포지션 내부 id = `window.__timelines[...]` 키,
  **세 개가 정확히 같아야** 합니다.
- 타임라인은 컴포지션당 **하나**, `gsap.timeline({ paused: true })`, 동기적으로 생성.
- `Math.random()` · `Date.now()` · `repeat: -1` 금지. 반복은
  `Math.max(0, Math.floor(전체시간 / 길이) - 1)` 로 유한하게.
- `drawSVG` 는 GSAP 유료 플러그인이라 **없습니다.** 선 그리기는
  `strokeDasharray` + `strokeDashoffset` 로 하세요.
- `fromTo` 의 시작값이 `opacity: 1` 이면 **타임라인 0초부터 보입니다.**
  나중에 등장해야 하는 요소는 `immediateRender: false` 를 주고,
  `tl.set(요소, { opacity: 0 }, 0)` 으로 바닥을 깔아두세요.
- 배경은 루트에 **한 번만** 깔고 씬은 오브젝트만 담습니다. 씬마다 배경을 다시 그리면
  컷에서 배경이 튑니다.

## 6. 검증은 눈으로도 하세요

`npx hyperframes check` 가 통과해도 **화면이 비어 있는 구간은 잡아주지 못합니다.**
실제로 오늘도 check 통과 상태에서 3.5초짜리 빈 화면이 있었고, 스냅샷으로만 발견했습니다.

```bash
npx hyperframes snapshot --at 5,12,20,30,45,60,75 --no-end
```

`snapshots/contact-sheet-*.jpg` 를 열어 **모든 씬을 눈으로 확인**하세요. 특히:

- 내레이터는 말하는데 화면이 빈 구간이 없는지
- 등장해야 할 요소가 미리 보이고 있지 않은지
- 텍스트가 잘리거나 겹치지 않는지

렌더 후에는 **결과물 MP4에서 직접 프레임을 뽑아** 한 번 더 확인하세요
(소스가 정상이어도 인코딩에서 빈 프레임이 나올 수 있습니다):

```bash
ffmpeg -ss 30 -i out.mp4 -frames:v 1 check.png
ffmpeg -i out.mp4 -af volumedetect -f null NUL    # 오디오가 무음이 아닌지
```

## 7. 의도된 겹침은 표시해 주세요

레이아웃 검사가 "텍스트 두 개가 겹친다"고 오류를 낼 때, 그게 **의도한 연출**이라면
해당 요소에 `data-layout-allow-overlap` 을 붙이면 통과합니다.
(예: 앞뒷면이 겹쳐 보이는 동전, 교차 전환 중인 두 단어)

억지로 레이아웃을 바꾸지 말고, 의도를 표시하세요.

## 8. scripts\ 안의 .ps1 파일을 고칠 때

**반드시 UTF-8 BOM 을 유지하세요.** Windows PowerShell 5.1 은 BOM 이 없는 .ps1 을
ANSI(CP949)로 읽어서 한글이 깨지고, **스크립트가 아예 실행되지 않습니다.**
(Missing argument / string is missing the terminator 같은 파싱 오류가 납니다)

대부분의 편집 도구는 BOM 없이 저장하므로, 수정한 뒤에는 다시 붙여 주세요:

```bash
python -c "
import glob
for f in glob.glob('scripts/*.ps1'):
    d = open(f,'rb').read()
    if not d.startswith(b'\xef\xbb\xbf'):
        open(f,'wb').write(b'\xef\xbb\xbf'+d)
"
```

또 PowerShell 5.1 에는 `&&`, `||`, 삼항 연산자가 없습니다. `if ($?) { }` 를 쓰세요.

## 10. 엔진 선택 — HyperFrames 또는 Remotion

이 저장소는 영상 엔진 두 개를 지원합니다. **사용자가 "Remotion"이라고 말하면 Remotion,
아니면 HyperFrames(기본)** 로 만듭니다. 디자인 시스템은 둘이 같습니다
(`remotion/src/kit/pastel.css` = `videos/*/assets/base.css` + `extra.css`).

| | HyperFrames | Remotion |
| --- | --- | --- |
| 위치 | `videos/<영상>/` (build.mjs → index.html) | `remotion/src/videos/<영상>/` + `remotion/public/<영상>/` |
| 예시 | `videos/ai-era-assignment/` | `remotion/src/videos/ai-era-assignment/` |
| 검증 | `npx hyperframes check` / `snapshot` | `npm run check`(tsc) / `npx remotion still <id> out/x.png --frame=N` |
| 렌더 | `npx hyperframes render -o out/x.mp4` | `npx remotion render <id> out/x.mp4` (`remotion/` 안에서) |

Remotion 작업 규칙:

- 새 영상은 `remotion/src/videos/ai-era-assignment/` 를 복사해서 시작하고 `src/Root.tsx` 에 등록한다.
- 씬은 `SCENES` 배열(큐 번호 `from` + `kind: 'say' | 'full'`)로 쓰고, 애니메이션은 `kit/anim.ts`
  헬퍼만 쓴다 (`mx(pop(t, T(12)))` 처럼). CSS transition/animation, `Math.random()` 금지 — `random('seed')`.
- 자막(SRT)은 `calculateMetadata` 에서 `loadSrt()` 로 읽어 props 로 넘긴다. 표기 교정은 `FIX`.
- 오디오(`public/<영상>/narration.m4a`)는 저장소에 올리지 않는다 (`remotion/README.md` 의 ffmpeg 명령).
- 렌더 후 MP4 에서 프레임을 뽑아 눈으로 확인하는 건 HyperFrames 와 똑같이 한다 (6번).
- Remotion 쪽은 시네마틱 판이다 (`kit/fx.tsx` · `kit/pro.css`: 오로라 배경 · 보케 · 그레인 · 카메라 펀치 인 ·
  임팩트 그라데이션 무대 · 키네틱 타이포 · 와이프 · 파티클 · 노래방 자막 · 캐릭터 리액션 · 효과음).
  'full' 씬은 자동으로 임팩트 무대(흰 글씨)가 되고, 컷은 와이프가 가린다.
- 여러 시점 확인은 `node scripts/stills.mjs <id> 30,91.2,181.6 out/stills` (번들 한 번으로 스틸 여러 장).
- 렌더 시간: 7분 15초 영상 약 18분. 그레인 때문에 원본이 크다(약 450MB) — 배포용은
  `ffmpeg -i out/x.mp4 -c:v libx264 -preset slow -crf 20 -c:a copy out/x-final.mp4` 로 다시 인코딩(약 250MB).

## 11. 실습 녹화 영상 → 모션그래픽 (두 트랙 방식, 사용자 확정)

사용자가 **본인 실습 녹화 영상 + 자막(SRT)** 을 주며 모션그래픽을 요청하면 이 방식으로 만든다.
기준 예시: `videos/claude-cli-install-1/` (`build.mjs` → `index.html`, `BRIEF.md`).

### 두 트랙

| 트랙 | 화면 | 하는 일 |
| --- | --- | --- |
| **① 모션그래픽 전용** | 실습 화면을 **완전히 덮는다** | 인트로·개념 설명 구간. 풀스크린 파스텔 장면으로 내용 전체를 시각화 |
| **② 실습 화면 + 최소 그래픽** | 실습 화면을 **그대로** 쓴다 | 핵심 내용에만 작은 카드를 화면의 **빈 영역**(작업 중인 부분을 가리지 않는 곳)에 살짝 올린다. 명령어·STEP·핵심 용어 정도 |

- 사용자가 구간별로 트랙을 지정하면 그대로 따른다. 지정이 없으면 인트로·이론 설명 = ①,
  화면 조작·설치·실습 = ② 로 나눈다.
- 구간 경계는 지정 시각 근처의 **자막 큐 경계에 스냅**한다 (문장 중간에서 끊지 않기).
  모든 그래픽 타이밍도 큐 번호(`T(n)` = 큐 시작, `TE(n)` = 큐 끝)에 고정한다.
- 원본 끝에 아웃트로가 있으면 그 위에 엔드카드("○편 완료 / 다음 편 …")를 얹는다.
- 오디오는 원본 영상 소리를 그대로 쓴다.

### 자막 — 사용자가 제공한 기본 자막을 그대로 쓴다

- 자막 모양은 **검정 바탕 박스 + 흰 글씨** (사용자 원본 자막 스타일). 새 스타일로 바꾸지 않는다.
- 원본 영상에 자막이 이미 박혀 있으면 ② 구간은 원본 자막이 그대로 보이므로 손대지 않는다.
- ① 구간은 덮개가 원본 자막까지 가리므로, **같은 SRT 문구를 같은 모양(검정 박스·흰 글씨, 같은 위치)으로
  다시 올린다.** 그래서 영상 전체에서 자막 모양이 끊김 없이 이어져야 한다.
- 자막 문구는 SRT 그대로. 군더더기 정리가 필요할 때만 `CAPFIX` 로 최소한만 고친다.

### 디자인

- 파스텔 글래스 카드 + Pretendard, 사용자 캐릭터 이미지(`assets/media/philosophy.png`) 활용.
- ② 구간 카드는 작고 짧게 — "살짝씩만". 화면을 많이 가리면 실패다.
- 질문 없이 렌더까지 끝내고, 완성본은 `2_완성 영상/` 에 `<원본 이름>_모션그래픽.mp4` 로 복사한다.

## 12. 폴더 정리 규칙 (사용자 확정)

사용자는 루트의 1~4번 폴더만 연다. 나머지는 전부 `5_etc/` 에 두고, 루트에 새 파일을 만들지 않는다.

| 폴더 (루트 기준) | 내용 |
| --- | --- |
| `1_작업할 영상/` | 사용자가 새 녹음·녹화·자막을 넣는 곳. **자료를 찾을 때 여기부터 본다** |
| `2_완성 영상/` | 완성 MP4 |
| `3_원본 보관/<영상 이름>/` | 작업이 끝난 원본. 납품 후 `1_작업할 영상/` 의 자료를 여기로 옮긴다 |
| `4_이미지 자료/` | 캐릭터 원본 등 |
| `5_etc/` | 프로그램·코드 전체. **폴더 이름에 한글 금지** (1번 참고) |
| `5_etc/videos/<영어이름>/` | HyperFrames 프로젝트. 이 폴더 바로 아래에 영상·자막을 두지 않는다 |
| `5_etc/upload-videos/` | GitHub 올리는 MP4 (Git LFS). 요청이 있을 때만 쓴다 |
| `5_etc/.env` | API 키 |

`1_`~`3_` 폴더의 Git 제외 규칙은 이 PC 의 `.git/info/exclude` 에 있다.

오래된 `BRIEF.md` 의 `../작업할 영상/…` 경로는 당시 기록이다. 해당 파일은 지금 `3_원본 보관/` 또는 `2_완성 영상/` 에 있다.

## 13. 영상 종류별 워크플로우 (사용자 확정)

요청이 오면 먼저 종류를 나눈다. 구분이 애매하면 **화면 조작을 보여 주는가**로 판단한다.

| 종류 | 입력 | 방식 |
| --- | --- | --- |
| **튜토리얼** (설치·실습·도구 사용법) | 실습 녹화 + SRT | 11번 두 트랙 방식. 기준: `videos/claude-cli-basics-2/` |
| **인사이트** (철학·AI에 대한 생각·에세이) | 본인 음성 녹음 + SRT | 아래 절차. 사진·영상·AI 이미지·모션그래픽이 화면을 채운다 |

### 인사이트 영상 절차

도구: `scripts/visuals.mjs`, 템플릿: `templates/insight-video/`. 키는 `5_etc/.env`
(`.env.example` 참고. `GEMINI_API_KEY`, `PIXABAY_API_KEY`). 키가 없을 때만 사용자에게 요청한다.

1. **프로젝트 생성** — `node scripts/visuals.mjs init videos/<영어이름>`
2. **소리·자막 준비** — 영상 폴더에서
   `ffmpeg -i "<원본>" -vn -c:a aac -b:a 192k assets/media/narration.m4a`, SRT 는 `assets/source.srt` 로 복사.
   SRT 가 없으면 `scripts/2-오디오추출-전사.ps1` 로 전사해서 만든다.
3. **샷 설계** — SRT 전체를 읽고 `BRIEF.md` 에 핵심 메시지를 적은 뒤 `shots.json` 을 쓴다.
   샷의 `from` 은 큐 번호이고, 끝은 다음 샷의 시작이다. **문장·생각이 바뀌는 큐에서만** 샷을 나눈다.
4. **Pixabay 후보** — `node ../../scripts/visuals.mjs search` → `edit/candidates/<id>/sheet.jpg` 를
   **눈으로 보고** 말의 뜻에 맞는 것을 골라 `pick` 에 id 를 적는다. 맞는 게 없으면 검색어를 바꾸거나 Gemini 로 돌린다.
5. **소재 확보** — `node ../../scripts/visuals.mjs fetch` → 받은 이미지를 **전부 눈으로 확인**한다.
   이상한 AI 이미지(손·글자 깨짐 등)는 프롬프트를 고쳐 다시 실행한다 (프롬프트가 같으면 `--force <id>`).
6. **모션 장면·조립** — `kind: "motion"` 장면을 `build.mjs` 의 `MOTION` 에 쓰고 `node build.mjs` → `npx hyperframes check`.
7. **검증·렌더** — 샷마다 중간 시점으로 `snapshot` → `render` → 6번대로 MP4 프레임·음량 확인.
8. **납품** — `2_완성 영상/` 에 `<원본 이름>_모션그래픽.mp4` 로 복사. `edit/CREDITS.txt` 내용을 유튜브 설명란용으로 함께 전달.

중간 질문 없이 끝까지 진행한다.

### 샷마다 무엇을 쓸까

| `kind` | 언제 | 예 |
| --- | --- | --- |
| `pixabay-video` | 분위기·전환·실제 세계의 장면. **움직임이 있어 가장 먼저 고려** | 도시의 밤, 파도, 걷는 사람 뒷모습 |
| `pixabay-image` | 구체적인 사물·장소 | 오래된 서가, 빈 교실 |
| `gemini` | 찾기 힘든 **은유·추상 개념**. 말에 꼭 맞는 그림이 필요할 때 | 빛의 벽 앞에 선 사람 |
| `motion` | **구조·대비·순서·숫자**를 설명할 때, 인트로·엔드카드 | "도구 vs 사고" 대비, 3단계 |

- **사용자 기준 (2026-10-31 ADHD 편):** Pixabay 이미지를 먼저 찾고, 알맞은 게 없을 때만 Gemini 로 **실제 사진 같은** 이미지를 만든다.
  움직임이 어울리는 몇몇 장면에는 Pixabay 무료 영상을 넣는다 (6분 영상에 10개 정도).
  영상 소재는 썸네일만 믿지 말고 **샷 길이 구간의 밝기를 잰다.** 번개·야경처럼 중간에 거의 까맣게 되는 소재는 빈 화면처럼 보이므로 쓰지 않는다.
  모션그래픽 전용 장면은 많이 넣지 않고 중요한 부분에만 임팩트 있게 넣는다 (6분 영상에 5장면 정도).
  대신 사진·영상 위에는 중요한 내용마다 **살짝** 강조를 얹는다 (사용자 추가 요청): `text` 의 `keyword` + 말하는 순서대로 나타나는 `items`,
  핵심 문장은 `quote`, 약점→강점은 `flip`. ADHD 편은 사진·영상 샷 50개 중 46개에 넣었다. 피사체를 가리지 않게 왼쪽 위에 둔다. 기준: `videos/adhd-ai-strengths/`.
  PPT 화면 영상을 받아도 화면은 쓰지 않고 소리만 쓴다. 자막 문구는 고치지 않는다.
- **사용자 추가 기준 (2026-10-31, 위 기준보다 우선):** 글자 박스만 얹은 판은 "밋밋하다"는 평가를 받았다. 사진·영상 위에도 말의 내용을 그림으로 보여 주는 그래픽을
  충분히 넣는다 (체크리스트·막대·게이지·흐름도·뒤집히는 카드·마인드맵 등, 큐마다 맞춰 등장). 샷 전환도 교차 페이드만 쓰지 않는다.
  기준: Remotion 판 `remotion/src/videos/adhd-ai-strengths/` (`beats.tsx` 가 장면별 그래픽, `gfx.tsx` 가 공용 부품).
- 출처는 영상에 넣지 않고 `edit/CREDITS.txt` 를 더보기란용으로 전달한다 (Pixabay 는 표기 의무 없음).
- 말이 끝난 뒤 긴 무음은 잘라낸다.
- 샷 길이는 5~10초. 정지 이미지는 12초를 넘기지 않는다 (build 가 경고).
- 핵심 문장에만 `text` 로 글자를 얹는다. `quote` = 영상 전체에서 가장 중요한 문장들(화면 중앙),
  `keyword` = 용어·개념(왼쪽 위). `<em>` 은 강조색. 자막과 같은 말을 모두 반복하지 않는다.
- 자막은 11번과 같은 검정 박스·흰 글씨. 문구는 SRT 그대로(`CAPFIX` 로 최소 교정).
- 영상은 어두운 시네마틱 톤으로 통일한다. 소재 색보정은 `visuals.mjs` 가 일괄 적용하고,
  Gemini 공통 스타일은 `shots.json` 의 `style` 한 줄로 고정한다. 샷마다 스타일을 바꾸지 않는다.

### 소재 규칙

- Gemini 모델은 `gemini-3.1-flash-lite-image` 고정(사용자 지정). 프롬프트는 영어로 쓴다. 해상도는 1K 뿐이다.
  문서 기준 약 $0.03/장이며, 프롬프트가 같으면 다시 생성하지 않는다. 글자 넣기는 AI 에 맡기지 않고 `text` 로 올린다.
- AI 이미지로 실존 인물을 그리지 않고, 실제 사건의 증거나 기록 사진처럼 쓰지 않는다.
- Pixabay 검색어는 영어. 얼굴이 뚜렷한 인물·로고·상표가 보이는 소재는 고르지 않는다.
  소재 원본을 저장소에 올리지 않는다 (`.gitignore` 처리됨). 기본 API 이미지는 최대 1280px 이라 살짝 부드럽다.
- API 키를 출력·커밋하지 않는다. 키는 `.env` 에만 둔다.
